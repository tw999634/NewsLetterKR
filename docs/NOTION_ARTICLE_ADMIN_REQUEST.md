# Notion 뉴스레터 하위 페이지 자동 작성: 관리자 요청 사항

> 2026-11-16 기준. 한국어와 일본어 뉴스레터는 각각 별도 부모 페이지 아래에 작성한다. 한국어 부모는 [【뉴스레터】GitHub Trending](https://app.notion.com/p/4197cfd0ca688017a33bc594146e02d4), 일본어 부모는 [【ニュースレター】GitHub Trending](https://app.notion.com/p/4197cfd0ca6880168268e04e28c8c1e6)이다. 각 언어·호당 하위 페이지 하나를 작성한다.

Markdown 파일을 하위 페이지로 작성하는 `newsletter.notion_publish` 모듈은 추가됐다. 현재 로컬·프로젝트 환경에 `NOTION_API_KEY`가 없어 실제 Notion 쓰기 검증은 아직 수행하지 않았다. GitHub Actions에는 발행 단계를 연결하지 않았다.

## 구현·검증 계획

1. **완료:** Markdown 파일 하나를 지정한 언어별 부모 페이지 아래 한 페이지로 작성하는 CLI, 명시적 `--publish` 스위치와 페이지 ID·URL 출력. 현재 Notion API의 `markdown_version: v2` 형식을 사용한다. 같은 제목이어도 재실행하면 새 페이지를 만든다.
2. **관리자 설정 후:** 팀 소유 Notion 연결과 비공개 시험 부모 페이지를 준비하고, 토큰을 로컬 비밀 환경 또는 GitHub Actions Secret `NOTION_API_KEY`에 등록한다. 비공개 시험 페이지에서 실제 쓰기와 링크·표 표시를 확인한다.
3. **공개 정책 확정 후:** 한국어 완성 보고서를 한국어 부모에 연결하고, 동일 내용을 일본어로 번역한 원고를 일본어 부모에 연결한다. 제목 규칙·발행 시각·장애 알림을 결정한 뒤 Actions 발행 단계를 추가한다.
4. **운영 검증:** 승인된 시범호를 언어별 부모 페이지에 발행하고 ID·URL·내용·공개 범위를 확인한다. 쓰기 응답이 불명확하면 자동 재시도 전에 부모 페이지를 조회한다.

사용자가 한국어·일본어 페이지를 각각 운영한다고 확인했고, 연결된 Notion 검색에서 위 두 부모와 각 시범 하위 페이지를 확인했다. 현재 생성 프로그램의 결과는 **한국어 조사 보고서 완성본**이며, 일본어 원고 자동 생성은 아직 없다. 사용자는 같은 호를 재실행하면 새 페이지를 추가하기로 정했다.

## 이번에 관리자에게 우선 확인할 정보

- 사용할 팀 소유 **Notion 내부 연결 이름·관리자**, 그리고 연결에 `Read content`·`Insert content` 권한을 주고 지정 부모 페이지와 비공개 시험 부모 페이지에 추가할 수 있는지.
- 토큰을 **GitHub Actions Secret `NOTION_API_KEY`에 관리자가 직접 등록**할 수 있는지. 토큰 값은 채팅이나 문서로 받지 않는다. 시험용 로컬 실행이 필요하면 안전한 비밀값 전달 경로도 지정해 달라.
- 한국어·일본어 부모 페이지와 새 하위 페이지의 **현재 공개 범위**, 비공개 시험 부모 페이지 ID, 발행 승인자와 승인된 원고를 확인할 위치.
- 한국어 보고서 완성본을 일본어로 그대로 번역할 때의 제목 규칙과 게시 시각. 재실행 시 새 페이지 추가는 확정됐다.

연결된 ChatGPT Notion 도구로 두 상위 페이지와 기존 [한국어](https://app.notion.com/p/4127cfd0ca6880479087c01740cf5465)·[일본어](https://app.notion.com/p/4127cfd0ca6880f99b8fc49023159c74) 하위 페이지를 읽었다. 이는 **ChatGPT 연결의 읽기 성공**만 뜻한다. 배포할 Python 프로그램의 Notion API 자격 증명, 하위 페이지 생성·수정 권한, 상위 페이지의 공개 범위는 아직 확인되지 않았다.

## 관리자에게 요청할 설정과 답변

1. **자동화용 연결:** 이 워크스페이스에서 운영할 팀 소유 Notion *내부 연결*을 만들거나 기존 연결의 이름과 관리자를 지정해 주세요. 배포된 GitHub Actions 또는 Cloud Run Jobs에서 사용할 연결이다. ChatGPT Notion 플러그인의 로그인과는 별개다. 조직 정책상 연결 생성·설치 승인이 필요하면 승인 담당자도 지정해 주세요. [Notion 인증 안내](https://developers.notion.com/guides/authorization/overview)
2. **기능 권한:** 새 하위 페이지 작성에는 `Insert content`, 상위 페이지와 작성 결과 확인에는 `Read content`를 허용해 주세요. 발행 후 오탈자 수정 기능을 추가할 경우에만 `Update content`도 허용해 주세요. 필요 없는 댓글·사용자 정보 권한은 요청하지 않습니다. [Notion 연결 기능 권한](https://developers.notion.com/reference/capabilities)
3. **상위 페이지 연결:** 위 한국어·일본어 부모 페이지 각각의 `••• → Connections/Add connections`에서 해당 내부 연결을 추가해 주세요. 연결이 두 페이지와 하위 페이지에 접근하는지 확인해 주세요. 상위 페이지가 다른 워크스페이스로 이동하거나 연결이 제거될 때 누가 관리할지도 정해 주세요. [페이지에 연결 추가](https://www.notion.com/help/add-and-manage-connections-with-the-api)
4. **비밀값 전달:** 내부 연결 토큰을 GitHub Actions Secrets의 승인된 비밀 저장소에 **관리자가 직접 등록**하거나 보안 담당자가 등록할 수 있도록 해 주세요. 토큰을 Markdown, 저장소, 일반 채팅에 적지 않습니다. 토큰 교체·폐기 담당자도 지정해 주세요. [Notion API 자격 증명 안내](https://developers.notion.com/guides/authorization/overview)
5. **공개 및 승인:** 두 상위 페이지가 `누구나 링크로 보기` 또는 Notion Site로 공개되어 있는지, 하위 페이지를 만들면 즉시 누구에게 보이는지 확인해 주세요. Notion은 하위 페이지에 상위 페이지의 권한을 상속하며, 공개된 Site의 하위 페이지도 기본적으로 공개됩니다. 비공개 시험 위치와 실제 게시 시각을 지정해 주세요. [공유 권한](https://www.notion.com/help/sharing-and-permissions), [Notion Site 공개 방식](https://www.notion.com/help/public-pages-and-web-publishing)
6. **페이지 형식:** 언어별 하위 페이지 제목 규칙, 표시 날짜·주차, 본문 템플릿, 기사 순서·분량, 출처 링크, 표·이미지 사용 기준을 정해 주세요. 기존 [한국어·일본어 시범본](EXAMPLES.md)을 형식 기준으로 삼을지도 확인해 주세요.
7. **재실행·수정:** 같은 기준 주차를 다시 실행하면 기존 하위 페이지를 유지하고 새 페이지를 추가한다. 발행 후 정정·철회가 필요할 때의 담당자와 별도 절차를 정해 주세요.
8. **완료 확인:** 생성된 페이지의 ID·URL을 어디에 기록할지, 부모 페이지 ID·제목·본문·출처 링크·공개 범위를 누가 확인할지 정해 주세요. 별도 비공개 시험 위치에서 권한을 먼저 확인하고, 두 상위 페이지에는 승인된 시범호를 각각 작성해 최종 확인하는 방식을 제안합니다.

## 이미 확정된 내용과 남은 결정

- **상위 위치:** 한국어·일본어 부모 페이지가 각각 있다.
- **페이지 단위:** 각 언어·호당 하위 페이지 하나다.
- **집계 기준:** 토요일 09:00 KST다. 실제 공개 시각은 아직 미정이다.
- **독자·산출물:** 한국어와 일본어 뉴스레터를 각각 작성한다. AI 뉴스는 호당 7건으로 계획한다.
- **미확인:** 배포용 내부 연결, API 권한과 토큰 저장, 두 부모 페이지의 공개 상태, 비공개 시험 위치, 발행 시각·제목 규칙.

## 연결 확인 절차

1. 워크스페이스 소유자가 내부 연결을 만들고 `Read content`·`Insert content`, 필요 시 `Update content`를 부여한다. 팀이 운영할 연결 이름과 담당자를 기록한다. [Notion 인증 안내](https://developers.notion.com/guides/authorization/overview)
2. 한국어·일본어 부모 페이지의 `••• → Connections/Add connections`에서 이 연결을 각각 추가한다. 조직 정책으로 연결 설치·추가가 제한돼 있다면 워크스페이스 관리자에게 허용을 요청한다. [Notion 연결 관리](https://www.notion.com/help/add-and-manage-connections-with-the-api)
3. 토큰을 선택한 배포 환경의 비밀 저장소에 등록하고 읽기 호출을 시험한다. 현재 ChatGPT 플러그인 연결은 배포된 Python 프로그램의 인증으로 사용할 수 없다.
4. 공개되지 않은 별도 시험 위치에서 페이지 생성을 시험한다. 승인된 시범호만 지정 상위 페이지에 생성하고 반환된 페이지 ID·URL·본문·출처 링크·공개 상태를 확인한다.

2026-11-14의 로그인 없는 HTTP GET에서는 일반 Notion HTML만 확인했다. 2026-11-15에는 연결된 ChatGPT Notion 도구로 상위 페이지와 기존 하위 페이지를 읽었다. 어느 확인도 배포용 연결의 **쓰기 권한**이나 외부 공개 상태를 증명하지 않는다.

## 관리자(사용자) 설정 요청

> 한국어 완성 보고서와 같은 내용을 번역한 일본어판을 각각 해당 언어의 GitHub Trending 부모 페이지 아래 하위 페이지로 자동 작성하려고 합니다. Notion 내부 연결을 만들고 `Read content`와 `Insert content`를 허용한 뒤, **두 부모 페이지 모두**에 연결해 주세요. 토큰은 GitHub Actions Secret `NOTION_API_KEY`에 직접 등록하고 값은 채팅이나 문서에 보내지 말아 주세요. 두 부모와 새 하위 페이지의 공개 범위, 비공개 시험 부모 페이지 ID, 언어별 제목 규칙과 발행 시각을 알려주세요. 재실행 시에는 새 페이지를 추가합니다.
